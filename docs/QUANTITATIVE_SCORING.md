# 量化打分与「其他」开放文本

## 配置与作答

1. 在未发布且尚无答卷的问卷中，进入「测评维度」，添加或编辑维度。
2. 普通、音色相似度、情绪准确度维度均可选择 GSB 或量化打分。量化打分配置最低分、最高分、步长，并为每个可选分值填写判定规则。
3. 分值允许 -999.99～999.99，最多两位小数，步长必须整除区间，最多 101 档、最少 2 档。修改范围会保留仍在范围内的规则；新档位须补齐规则才能保存。
4. 选择维度类型「其他」后，设置填写引导与是否必填。两个音频各有一个文本输入，默认选填，每侧最多 5000 字。
5. 答卷按维度对照显示音频 A（左侧）、B（右侧），各自独立打分，允许同分和零分。点选分值显示对应规则，也可展开全部规则。情绪准确度、音色相似度沿用指定组别范围。
6. 量化分值、文本观察和 GSB 均支持自动保存、刷新后同名续答；所有必填项完成后方可提交。整卷、旧随机抽样和固定子问卷使用相同评分校验，固定子问卷只校验分配的题目。

## 历史数据与统计

- 历史维度 `scoringConfig = NULL` 等同 GSB，不改写或推算历史答案。新建问卷预置维度仍默认 GSB，管理员可在发布前逐个切换为量化。
- 已发布或已有任何答卷时，评分维度的新增、修改、删除均被锁定。无答卷可以先下线再改；已有答卷请复制问卷后设置新量表，避免历史分数失去判定依据。
- 答卷详情显示两侧分值/文本。Excel 分开导出两侧的音频 ID、原文件名、模型、分值和文本，并保留组别、配对 ID、维度 ID、子问卷编号；另有评分规则工作表。
- 单问卷「查看分析」按维度和实际模型显示量化评分次数、平均分、最低分、最高分，以及非空文本观察数。只统计选中的已提交/已评分答卷；同一音频在多个配对中被重复评分时，每次分别计数。
- 量化分数不换算为 GSB，不混入胜率或显著性分析，也不跨不同量表计算统一答卷总分。跨问卷聚合页面当前仅统计 GSB；量化请在单问卷分析中查看。
- 「其他」仅收集、保存和导出原始文本供后续自然语言分析，本次不自动调用模型或产生分析费用。

## 部署

新增两列均为可空 JSON：`evaluationDimensions.scoringConfig`、`answers.audioEvaluation`。

先确认目标环境和备份，使用部署环境注入的 `DATABASE_URL`，在应用目录执行：

```sh
pnpm db:migrate:0012
pnpm db:check:0012
```

没有 pnpm 时可使用部署环境的 Node.js：

```sh
node scripts/apply-0012-migration.mjs --apply
node scripts/apply-0012-migration.mjs --check
```

脚本默认只检查。`--apply` 只添加缺失列，重复执行安全，不删除或重写历史记录；已有列类型不符会报错并要求人工检查。若 0010/0011 尚未部署，也需先完成相应迁移。`pnpm start` 和 `start.sh` 使用统一入口 `scripts/prepare-database.mjs` 检查 0010、0011、0012；默认缺列会停止启动。

### 无法进入 WebShell 时

可在部署平台通过环境变量显式授权启动前补字段，无需进入容器或运行 pnpm：

1. 确认目标环境的 `DATABASE_URL` 正确，数据库已备份。生产与预发分别处理，不混用连接；执行账号需要对应表的 ALTER 权限。
2. 选择包含 `scripts/prepare-database.mjs` 的修复版本重新构建镜像，旧提交 `a608a73` 不支持该开关。
3. 在部署环境变量中设置 `DB_MIGRATE_ON_START=1`，然后发布修复镜像。不要将开关写死在镜像中，也不要给全局数据库迁移权限。
4. 启动入口先检查三个迁移：连接、类型或权限检查失败就停止，尚不执行补列；仅在确认为缺字段时执行相应脚本，再完整复核。无需开启 HTTP 服务，所有检查通过才会启动应用。
5. 在部署平台容器日志中查看 `[database]` 输出；日志也写入 `/export/log/audio-eval/app.log`。看到 `0010/0011/0012 全部通过，可以启动应用` 说明数据库检查通过；仍需确认后续应用监听、健康检查成功，不能将此日志等同发布成功。
6. 成功后把 `DB_MIGRATE_ON_START` 改回 `0`（或删除），以后恢复只检查。

### 配置为 1，启动日志仍显示 0

不要只重复重启。容器入口先输出 `[start_container.sh] injected DB_MIGRATE_ON_START=...`，管理员启动脚本输出 `[start.sh] shell DB_MIGRATE_ON_START=...`，数据库准备脚本输出最终 `[database]` 值。这些诊断不打印连接串、密码或密钥。

- 入口显示 `unset/empty` 或 `0`：该容器收到的运行时配置未开启开关。核对本次发布的应用、环境、分组及配置版本；请平台管理员确认实际注入值。代码不能从管理页面读取尚未注入的配置。
- 入口显示 `1`，shell 显示 `0` 或空：切换用户或加载 `/etc/profile`、`/export/env`、`/home/admin/.jdos_env` 时存在环境差异。修复后的 JDOS 启动脚本以入口新生成的 `/opt/app/.env` 快照为准，在数据库准备和应用启动时使用同一快照，覆盖 shell 的旧同名值；不只覆盖迁移开关，也保留配套的目标数据库配置。
- 入口未收到开关时，快照明确保存 `0`，防止旧 profile 中的 `1` 意外开启迁移。入口收到 `1` 时必须同时收到 `DATABASE_URL`，不从旧 profile 推断迁移目标。
- 快照缺失、不可读或缺少合法开关时停止启动，不回退到未知配置。需重新构建同时包含两个启动脚本修复的镜像；单独重建旧镜像的容器不会更新脚本。`pnpm start` 的本地环境优先级不变。

开关只允许 `0`/`1`，不填默认只检查；重试只补缺列。每个子检查/补列最多等待 120 秒，失败或超时不启动应用；DDL 超时后数据库端操作可能仍在进行，请先由数据库管理员确认状态。多个实例启动、数据库锁或平台健康检查期限可能影响执行；需要时由运维协调发布前任务或检查等待时间。此开关不能修复无数据库权限、网络不通或平台初始化失败；这些错误仍需按部署日志处理。

代码推送不等于部署；未显式开启 `DB_MIGRATE_ON_START=1` 就不会自动迁移线上数据库。回滚旧应用时保留新增列和已有 JSON 数据，不执行删列操作。

## 验证

`pnpm check`、`pnpm test`、`pnpm build`。

真实 MySQL 集成测试默认跳过，需提供两个互相独立的空测试库：`SCORING_TEST_DATABASE_URL`（本地主机、库名以 `scoring_test_` 开头）和 `SUBQUESTIONNAIRE_TEST_DATABASE_URL`（本地主机、库名以 `sub_questionnaire_test_` 开头）。测试会拒绝非本地或非空库，禁止配置生产库。评分集成测试先创建旧结构和 GSB 数据，再验证迁移检查、重复迁移、历史数据保留以及整卷/子问卷评分全流程。

启动前自动补字段另有 `STARTUP_TEST_DATABASE_URL`，仅允许本地 `startup_test_` 前缀的空库；覆盖默认不修改、类型冲突不写入、显式授权后补齐三个迁移和幂等重试。
