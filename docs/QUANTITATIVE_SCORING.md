# 量化打分与「其他」开放文本

## 配置与作答

1. 在未发布且尚无答卷的问卷中，进入「测评维度」，添加或编辑维度。
2. 普通、音色相似度、情绪准确度维度均可选择 GSB 或量化打分。量化打分配置最低分、最高分、步长，并为每个可选分值填写判定规则。
3. 分值允许 -999.99～999.99，最多两位小数，步长必须整除区间，最多 101 档、最少 2 档。修改范围会保留仍在范围内的规则；新档位须补齐规则才能保存。
4. 选择维度类型「其他」后，设置填写引导与是否必填。两个音频各有一个文本输入，默认选填，每侧最多 5000 字。
5. 答卷按维度对照显示音频 A（左侧）、B（右侧），各自独立打分，允许同分和零分。点选分值显示对应规则，也可展开全部规则。情绪准确度、音色相似度沿用指定组别范围。
6. 量化分值、文本观察和 GSB 均支持自动保存、刷新后同名续答；所有必填项完成后方可提交。整卷、旧随机抽样和固定子问卷使用相同评分校验，固定子问卷只校验分配的题目。

## 历史数据与统计

- 历史维度 `scoringConfig = NULL` 等同 GSB，不改写或推算历史答案。新建问卷预置维度仍默认 GSB，管理员可在发布前逐个切换为量化。
- 已发布或已有任何答卷时，评分维度的新增、修改、删除均被锁定。无答卷可以先下线再改；已有答卷请复制问卷后设置新量表，避免历史分数失去判定依据。
- 答卷详情显示两侧分值/文本。Excel 分开导出两侧的音频 ID、原文件名、模型、分值和文本，并保留组别、配对 ID、维度 ID、子问卷编号；另有评分规则工作表。
- 单问卷「查看分析」按维度和实际模型显示量化评分次数、平均分、最低分、最高分，以及非空文本观察数。只统计选中的已提交/已评分答卷；同一音频在多个配对中被重复评分时，每次分别计数。
- 量化分数不换算为 GSB，不混入胜率或显著性分析，也不跨不同量表计算统一答卷总分。跨问卷聚合页面当前仅统计 GSB；量化请在单问卷分析中查看。
- 「其他」仅收集、保存和导出原始文本供后续自然语言分析，本次不自动调用模型或产生分析费用。

## 部署

新增两列均为可空 JSON：`evaluationDimensions.scoringConfig`、`answers.audioEvaluation`。

先确认目标环境和备份，使用部署环境注入的 `DATABASE_URL`，在应用目录执行：

```sh
pnpm db:migrate:0012
pnpm db:check:0012
```

没有 pnpm 时可使用部署环境的 Node.js：

```sh
node scripts/apply-0012-migration.mjs --apply
node scripts/apply-0012-migration.mjs --check
```

脚本默认只检查。`--apply` 只添加缺失列，重复执行安全，不删除或重写历史记录；已有列类型不符会报错并要求人工检查。若 0010/0011 尚未部署，也需先完成相应迁移。`pnpm start` 和 `start.sh` 均检查 0010、0011、0012，任一缺列会停止启动。

代码推送不等于部署，也不会自动迁移线上数据库。回滚旧应用时保留新增列和已有 JSON 数据，不执行删列操作。

## 验证

`pnpm check`、`pnpm test`、`pnpm build`。

真实 MySQL 集成测试默认跳过，需提供两个互相独立的空测试库：`SCORING_TEST_DATABASE_URL`（本地主机、库名以 `scoring_test_` 开头）和 `SUBQUESTIONNAIRE_TEST_DATABASE_URL`（本地主机、库名以 `sub_questionnaire_test_` 开头）。测试会拒绝非本地或非空库，禁止配置生产库。评分集成测试先创建旧结构和 GSB 数据，再验证迁移检查、重复迁移、历史数据保留以及整卷/子问卷评分全流程。
